# lab3 实验报告

## 实现的功能

本次实验实现了 `spawn` 和 `set_priority` 两个系统调用，并将调度算法改为 stride 调度。`spawn` 根据程序名直接加载 ELF 创建子进程，不复制父进程的地址空间。`set_priority` 拒绝小于 2 的优先级，并按优先级重新计算步长。调度时选取就绪队列中 stride 最小的进程，取出后累加其步长。此外，将上一章的 `get_time`、`mmap` 和 `munmap` 迁移到了本章的进程结构上。

## 问答作业

### 1. 实际是否轮到 p1 执行

不会。p2 运行一个时间片后，stride 变为 250 + 10 = 260，超出 8 位无符号整数的范围，实际保存的值为 4。调度器比较时认为 4 小于 255，于是再次选中 p2。

### 2. 为什么 `STRIDE_MAX – STRIDE_MIN <= BigStride / 2`

优先级不小于 2，所以每个进程的步长都不超过 BigStride / 2。初始时所有进程的 stride 相同，结论成立。假设某一时刻结论成立，调度器选出 stride 最小的进程，为其加上不超过 BigStride / 2 的步长。该进程的新 stride 不超过原最小值加 BigStride / 2；其余进程的 stride 都不小于原最小值，新的最小值也不会小于原最小值。因此调度之后，最大值与最小值的差仍不超过 BigStride / 2。

### 3. 考虑溢出的比较器

由上一题，真实 stride 之差的绝对值不超过 BigStride / 2。用 64 位无符号数保存时，将两数相减的结果按有符号数解释，即可得到正确的大小关系：

```rust
use core::cmp::Ordering;

struct Stride(u64);

impl PartialOrd for Stride {
    fn partial_cmp(&self, other: &Self) -> Option<Ordering> {
        if (self.0.wrapping_sub(other.0) as i64) < 0 {
            Some(Ordering::Less)
        } else {
            Some(Ordering::Greater)
        }
    }
}

impl PartialEq for Stride {
    fn eq(&self, _other: &Self) -> bool {
        false
    }
}
```

以 8 位、BigStride = 255 为例：125 − 255 回绕后为 126，作为有符号数为正，故 125 > 255；129 − 255 回绕后为 130，作为有符号数为 −126，故 129 < 255。与题目给出的结果一致。

另外，`BinaryHeap` 是大根堆，若要用它弹出最小的 stride，还需要将上述比较结果反转，或者用 `core::cmp::Reverse` 包装。
