# lab4 实验报告

## 实现的功能

本次实验在 easy-fs 中支持了硬链接，并实现了 `linkat`、`unlinkat` 和 `fstat` 三个系统调用。磁盘 inode 中新增链接计数，新建文件时为 1。`linkat` 在根目录中添加一个指向同一 inode 的目录项，并将链接计数加一；`unlinkat` 删除目录项并将链接计数减一，计数为零时回收该文件的数据块和 inode。`fstat` 返回文件的 inode 编号、类型和链接数。此外，将前两章的 `spawn`、`set_priority`、stride 调度、`mmap` 等功能迁移到了本章。

## 问答作业

### ch6

在 easy-fs 中，root inode 起着什么作用？如果 root inode 中的内容损坏了，会发生什么？

easy-fs 只有一级目录，root inode 就是这唯一的目录，其数据块中存放着所有文件的目录项，即文件名与 inode 编号的对应关系。打开、创建、链接和删除文件，都要先在 root inode 中查找或修改目录项。

如果 root inode 的内容损坏，例如大小字段或数据块编号出错，内核将无法正确读取目录项，也就无法通过文件名找到任何文件。此时文件的数据可能仍然完好地保存在磁盘上，但已经无法访问。如果损坏的数据块编号恰好指向其他文件的数据，后续对目录的写操作还可能破坏这些文件。

### ch7

（1）举出使用 pipe 的一个实际应用的例子。

在 shell 中执行 `ps aux | grep nginx`，shell 创建一个管道，将 `ps` 的标准输出连接到管道的写端，将 `grep` 的标准输入连接到读端。`ps` 输出的进程列表经过 `grep` 筛选后，只显示与 nginx 相关的行。两个程序都不需要知道对方的存在。

（2）如果需要在多个进程间互相通信，为每一对进程都建立管道非常繁琐，请设计一个更易用的多进程通信机制。

可以设计一种带名字的消息队列。内核维护一张以名字为索引的队列表，进程通过名字打开队列，不必像匿名管道那样依赖父子关系传递文件描述符。每条消息作为一个整体发送和接收，保留消息边界。多个进程可以向同一个队列发送消息，也可以从中接收，因此 n 个进程之间通信只需要按需建立少量队列，不必两两建立管道。队列的打开计数归零时由内核回收。
