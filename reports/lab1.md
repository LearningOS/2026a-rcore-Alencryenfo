# lab1 实验报告

## 实现的功能

本次实验实现了 `sys_trace` 系统调用。在任务控制块中为每个任务维护一张系统调用计数表，系统调用进入分发函数时先为对应编号计数，因此查询结果包含本次调用。`trace` 支持三种请求：读取用户地址处的一个字节、向用户地址写入一个字节、查询当前任务某个系统调用的累计次数；其余请求返回 -1。由于本章尚未启用分页，读写请求直接按用户给出的地址访问。

## 简答作业

### 1. 三个 bad 测例的运行结果

使用的 SBI 为 RustSBI Prototyper 0.4.1。

`ch2b_bad_address` 向地址 0 写入一个字节，触发 StorePageFault。内核输出 `[kernel] PageFault in application, bad addr = 0x0, ...`，随后结束该程序并运行下一个。

`ch2b_bad_instructions` 在 U 模式下执行 `sret`。该指令只能在 S 模式及以上执行，因此触发非法指令异常，内核输出 `[kernel] IllegalInstruction in application, kernel killed it.`。

`ch2b_bad_register` 在 U 模式下读取 `sstatus`。访问 S 模式 CSR 同样触发非法指令异常，内核的处理与上一个测例相同。

三个程序都被内核捕获并终止，没有影响其他程序的运行，说明特权级隔离是有效的。

### 2. `trap.S` 中的 `__alltraps` 与 `__restore`

（1）刚进入 `__restore` 时，`sp` 指向内核栈上保存好的 Trap 上下文。`__restore` 有两种使用情形：一是 `trap_handler` 处理完毕后，顺序执行到 `__restore` 返回用户态；二是任务第一次运行时，任务上下文中的 `ra` 被设为 `__restore`，切换到该任务后由此进入用户态。

（2）L43–L48 恢复了 `sstatus`、`sepc` 和 `sscratch`。`sstatus` 的 SPP 位决定 `sret` 之后回到哪个特权级，SPIE 位决定返回后是否开启中断；`sepc` 是 `sret` 之后执行的第一条指令的地址；`sscratch` 被写入用户栈指针，供 L60 交换回 `sp`。

（3）`x2` 即 `sp`，此时它指向内核栈，用户栈指针已经单独放在 `sscratch` 中，最后通过 L60 恢复。`x4` 即 `tp`，用户程序不会使用它，保存时也没有写入 Trap 上下文，因此恢复时同样跳过。

（4）L60 执行后，`sp` 指向用户栈，`sscratch` 指向内核栈，为下一次陷入做好准备。

（5）状态切换发生在 `sret`。执行 `sret` 时，CPU 将特权级设为 `sstatus.SPP` 所记录的值，这里为 U 模式，并跳转到 `sepc` 处，因此进入用户态。

（6）L13 执行后，`sp` 指向内核栈，`sscratch` 保存用户栈指针。

（7）用户程序执行 `ecall`，或者出现异常、中断时，硬件会从 U 模式进入 S 模式，并跳转到 `stvec` 所指向的 `__alltraps`。本实验中的系统调用就是由 `ecall` 引起的。
